# Task-142: Buzz 저장소를 MySQL로 옮긴다

## Background

Buzz는 MongoDB 문서 하나에 본문, 공개 대상, 사용자별 읽음 기록, 댓글을 저장한다. MongoDB를 제거할 수 있도록 Buzz의 저장소를 기존 MySQL로 통합한다. 현재 MongoDB를 사용하는 Notification의 이전은 별도 작업이다.

## Objective

Buzz 본문, 공개 대상과 사용자별 읽음 상태, 댓글을 MySQL에 저장하고 조회한다. 기존 Buzz API와 공개 범위, 댓글 권한을 유지하며, 생성 후 6시간이 지난 Buzz와 그에 속한 데이터를 정리할 수 있게 한다.

## Decision

- Buzz는 발행 시 볼 수 있는 사람을 확정하는 글이다. 기존 수동·라벨·피벗 지정 규칙으로 정해진 공개 대상을 발행과 함께 저장한다. 그 이후 관계나 라벨이 바뀌어도 발행 당시 명단을 다시 계산하지 않는다. 기존 목록 조회의 제외 규칙은 유지한다.
- 본문, 공개 대상과 읽음 상태, 댓글을 관계형으로 분리한다. 읽음 처리나 댓글 수정에 전체 공개 대상과 댓글을 불러올 필요가 없도록 한다. 구체적인 스키마와 쿼리는 구현 계획에서 정한다.
- 생성 후 6시간이 지나면 물리 삭제 시점과 무관하게 사용자에게 만료된 것으로 처리한다. 전환 전에 발행한 Buzz도 원래 만료 시각까지 이용할 수 있어야 한다. 전환 방식은 구현 계획에서 정한다.

## Out of Scope

- Notification 이전, MongoDB 인프라 제거
- 대댓글, 가벼운 반응, 피드 도입, 공개 범위나 수신자 지정 방식의 제품 변경
- Social 상호작용 점수 정책 변경, 이미지 저장 방식 변경

## Acceptance Criteria

- Buzz 발행, 보낸·받은 목록과 상세 조회, 읽음 처리, 미확인 작성자 조회, 댓글 작성·수정·삭제, Buzz 삭제가 MySQL에서 동작한다. Buzz 실행 경로에 MongoDB 의존이 남지 않는다.
- 기존 API 응답 형식, 공개 대상에 따른 접근 제어, 목록의 제외 규칙, 최근 댓글 20개의 순서와 비공개 댓글의 열람·수정·삭제 권한이 유지된다. 최근 20개에 포함되지 않은 댓글도 기존 권한으로 수정·삭제할 수 있다.
- Buzz 본문과 공개 대상은 함께 저장된다. 공개 대상 사용자의 댓글 추가와 읽음 처리 중 하나가 실패하면 둘 다 반영되지 않는다. 동시에 여러 사용자가 댓글을 달거나 읽어도 서로의 변경을 덮어쓰지 않는다.
- 만료된 Buzz는 목록·상세·미확인 작성자 조회에 나타나지 않고 새 댓글이나 읽음 기록을 남길 수 없다. 만료 정리 또는 작성자의 삭제 후에는 해당 Buzz의 공개 대상·읽음·댓글 데이터가 남지 않는다.
- 저장에 실패한 발행이나 댓글 작성은 알림과 Social 상호작용을 발생시키지 않는다. 성공한 발행과 댓글 작성은 기존 후속 동작을 유지한다.
- 전환으로 미만료 Buzz가 조기에 사라지지 않는다. 전환 전에 발행한 글이 전환 후에도 원래 ID와 만료 시각으로 조회되는지 확인한다.
