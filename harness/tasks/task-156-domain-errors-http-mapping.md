# Task-156: 도메인 실패 이유와 HTTP 오류 매핑을 분리한다

## Background

공통 ErrorCode 계약은 HttpStatus를 요구하고 BusinessException은 getHttpStatus()를 제공한다. SocialErrorCode를 비롯한 도메인 오류 코드가 HTTP 상태를 보유하며, GlobalExceptionHandler는 이 값을 응답에 그대로 사용한다. 이는 HTTP 응답 변환을 웹 계층의 책임으로 정한 아키텍처와 어긋난다. SocialErrorCode에는 direction 요청 값 검증처럼 업무 규칙과 구분할 필요가 있는 오류도 섞여 있다.

## Objective

도메인 예외는 업무상 실패 이유를 표현하고, 웹 어댑터가 이를 HTTP 상태와 오류 응답으로 변환하도록 공통 오류 계약과 각 모듈의 의존성을 분리한다. 기존 외부 오류 응답 계약은 보존한다.

## Decision

- 도메인 예외와 업무 오류 식별자는 domain에 유지하되 HTTP 상태와 HTTP 응답 변환 책임은 웹 계층에 둔다. HttpStatus를 정수 상태 코드로 바꾸는 방식은 책임 분리가 아니므로 사용하지 않는다.
- 공통 ErrorCode와 BusinessException을 사용하는 모든 모듈의 영향을 함께 검토한다. Social만의 국소 변경으로 끝내지 않는다.
- 기존 명시적 오류 식별자, 사용자 메시지와 로그 컨텍스트의 분리는 유지한다. 예외 클래스명에서 API 오류 식별자를 파생하지 않는다.
- 웹 요청 형식이나 유스케이스 전용 조건에 해당하는 오류는 실제 발생 위치를 확인하여 책임 계층에 맞게 분류한다.
- HTTP 상태, 오류 식별자, 응답 메시지와 본문 형식을 유지한다. 보안 필터의 인증·인가 실패 응답도 공통 계약 변경의 영향을 확인한다.
- ARCHITECTURE.md의 도메인 예외와 웹 어댑터 설명은 해당 구현 변경과 같은 커밋 단위에서 갱신한다. 미구현 구조를 먼저 정본에 반영하지 않는다.

## Out of Scope

- 저장소 계약 이동과 도메인 조회 책임 정리(task-155).
- 업무 규칙 변경, 오류 응답 계약 개편, 다국어 메시지 체계 도입.

## Acceptance Criteria

- 도메인 예외·오류 코드 및 이들이 사용하는 공통 오류 계약에 HTTP 상태 타입, 상태 값, HTTP 응답 변환 책임이 남지 않는다.
- 웹 계층에서 각 업무 오류의 HTTP 상태를 결정하며, 기존 오류 매핑이 누락되지 않았음을 검증한다.
- 기존 도메인 실패 사례와 웹 요청 검증, 인증·인가 실패의 HTTP 상태·오류 식별자·메시지·본문 형식이 유지된다.
- 로그 컨텍스트는 유지되고 내부 예외 정보가 사용자 응답에 새로 노출되지 않는다.
- 영향받은 모듈의 컴파일과 관련 테스트가 통과하고, ARCHITECTURE.md가 실제 예외 처리 책임과 일치한다.
