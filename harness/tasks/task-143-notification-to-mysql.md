# Task-143: Notification 저장소를 MySQL로 옮긴다

## Background

Notification은 기기 토큰을 MySQL에, 알림 이력을 MongoDB에 저장한다. 알림 이력도 기존 MySQL로 옮겨 Notification의 저장소를 통합한다.

## Objective

알림 이력을 MySQL에 저장하고 조회한다. 기존 알림함 API와 Firebase FCM 발송 흐름을 유지하고, MongoDB TTL이 맡았던 30일 보관 정책을 MySQL에서도 적용한다.

## Decision

- 전환 시점에 생성 후 30일이 지나지 않은 알림은 기존 ID, 생성 시각, 수신자, 메타데이터, 읽음·발송 상태를 보존한다. 이관 때문에 보관 기간이 다시 시작되거나 푸시가 재발송되지 않아야 한다.
- 사용자별 알림과 수신자가 없는 전체 공지의 구분을 유지한다. 30일이 지난 알림은 물리 정리 시점과 무관하게 알림함에서 만료로 처리한다.

## Out of Scope

- Buzz 이전과 두 이전 완료 후의 공용 MongoDB 의존성, 배포 설정 및 인프라 제거
- 기기 토큰 관리 및 FCM 발송 정책 변경, 재발송이나 아웃박스 도입

## Acceptance Criteria

- 개인 알림과 전체 공지의 생성·발송 상태 기록, 사용자별 최신순 목록, 미읽음 집계, 읽음 처리와 삭제가 MySQL에서 동작한다. Notification 실행 경로에 MongoDB 의존이 남지 않는다.
- 기존 API의 ID 형식과 응답 형태, 메타데이터의 값과 타입, 읽음·삭제 권한을 유지한다. 전체 공지는 기존처럼 개인 알림 목록과 미읽음 집계에 포함되지 않는다.
- 읽음 처리와 발송 상태 변경이 겹쳐도 각 변경이 유지되고, 삭제한 알림이 늦은 발송 상태 변경으로 다시 생성되지 않는다.
- 생성 후 30일이 지난 알림은 목록과 미읽음 집계에서 제외되며 읽음 처리 대상에서 빠진다. 보관 기간이 지난 데이터는 물리적으로 정리된다.
- 이관된 알림을 기존 ID로 읽음 처리하거나 삭제할 수 있다. 전환을 재실행해도 알림이 중복 생성되거나 푸시가 다시 발송되지 않는다.
