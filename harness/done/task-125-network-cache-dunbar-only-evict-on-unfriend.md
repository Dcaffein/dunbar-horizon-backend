# Task-125: 관계망 캐시를 기본 관계망 150 서클 하나로 줄이고, 라벨 관계망 조회를 가볍게 한다

## Background

관계망 캐시는 task-23에서 들어왔다. 기본 관계망은 서클 네 개(5·15·50·150)를 각각 캐싱하고, 라벨 관계망은 라벨마다 하나를 캐싱한다. 무효화는 친구 추가, 친구 삭제, 라벨 멤버 변경 세 이벤트에서 일어나고 나머지는 TTL 10분에 맡긴다.

캐시가 실제로 필요한 것은 연산이 가장 무거운 150명 크기의 기본 관계망뿐이라고 판단했다. 작은 서클과 라벨 관계망은 캐시 없이 조회해도 된다.

그런데 라벨 관계망도 지금은 `DUNBAR`를 고정으로 넘겨 최대 150명을 연산한다. 라벨 멤버 수에는 도메인 상한이 없으므로 큰 라벨은 기본 관계망 150 서클과 같은 크기가 된다. 그래서 라벨 관계망 조회를 50명으로 줄이고, 나머지 멤버는 UI가 기본 관계망처럼 동적으로 붙이게 한다. 동적 추가에 쓰는 `GET /api/v1/network/edges`는 화면에 떠 있는 노드 목록을 클라이언트에게서 받으므로 라벨 화면에서도 그대로 쓸 수 있다.

상한만 줄여서는 라벨 관계망이 가벼워지지 않는다. 라벨 쿼리는 라벨 멤버에서 출발해 me와의 Friendship을 찾는데, 플래너가 멤버마다 그 멤버의 Friendship을 전부 펼친 뒤 `Expand(Into)`로 me와 이어진 것을 고른다. 이 비용은 `LIMIT`보다 앞에서 나므로 상한과 무관하다. perf 데이터(7688)에서 친구 전원을 붙인 임시 라벨로 PROFILE한 결과는 아래와 같다(`Neo4jOptimizeTest/profiling/results/network_limit_50_vs_150_20261029_1651.md`).

| 유저(친구 수) | 운영 라벨 쿼리 limit 50 | limit 150 | me에서 출발 limit 50 | 기본 관계망 limit 150 |
|---|---:|---:|---:|---:|
| 3 (190) | 344,451 / 8.9MB | 492,066 / 8.9MB | 69,402 / 41KB | 216,246 / 121KB |
| 3706 (203) | 406,591 / 10.8MB | 570,891 / 10.8MB | 80,030 / 41KB | 243,459 / 121KB |

운영 쿼리 그대로라면 50명 라벨이 캐시로 남길 기본 관계망 150 서클보다 무겁다. 그래서 라벨 쿼리의 출발점을 me로 바꾼다.

무효화 이벤트도 다시 본다.

- 친구 추가는 즉시 반영하지 않아도 된다. 화면이 친구 목록으로 노드를 동적으로 붙이고 뗄 수 있고, 친구가 됐다고 해서 친한 친구 관계망에 바로 나타나야 하는 것도 아니다.
- 친구 삭제는 즉시 반영해야 한다. 반영이 늦으면 끊긴 친구가 친구 목록에서는 사라졌는데 관계망에는 계속 보인다.

## Objective

Redis에 남는 관계망 캐시는 기본 관계망의 150 서클(`DUNBAR`) 하나다. 다른 서클과 라벨 관계망은 매번 Neo4j에서 조회하고, 라벨 관계망은 me의 Friendship에서 출발해 친밀도 상위 50명까지만 돌려준다. 캐시를 지우는 이벤트는 친구 삭제 하나이고, 삭제가 커밋되면 양쪽 유저의 150 서클 캐시가 지워진다. 친구 추가와 라벨 멤버 변경은 캐시를 건드리지 않으며 추가된 친구는 TTL이 지나야 보인다.

## Decision

### 캐시 키와 TTL은 그대로 둔다

키 형식은 `dunbar:network:default:{userId}:DUNBAR`, TTL은 10분으로 유지한다. 배포 전에 쌓인 다른 서클과 라벨 키는 TTL이 지나면 자연히 사라지므로 따로 지우지 않는다.

### 라벨 관계망 상한은 150에서 50으로 바꾼다

task-23은 라벨 관계망이 그룹 전체의 결속을 보여주는 용도라며 슬라이더 없이 150명 천장 하나만 두었다. 이번에 그 결정을 바꾼다. 처음 화면에는 50명만 연산해 내려주고, 그보다 큰 라벨은 UI가 동적 추가로 채운다. 슬라이더는 이번에도 두지 않는다.

### 라벨 멤버십은 패턴 술어로 거른다

[0] 단계는 `me → friend WHERE (label)-[:ATTACHED_TO]->(friend)` 모양으로 쓴다. 같은 측정에서 맵으로 거르는 두 방식(라벨 멤버 맵, me의 친구 맵)도 결과가 같고 DB Hits도 0.5% 안쪽으로 같았지만, GlobalMemory가 1.6~33MB로 커졌다. 패턴 술어 버전은 41~121KB로 기본 관계망과 같다. 응답 시간은 재지 않았다.

## Acceptance Criteria

- `DUNBAR` 서클의 기본 관계망을 조회하면 Redis에 저장되고, 다른 서클과 라벨 관계망을 조회하면 저장되지 않는다.
- 친구 삭제가 커밋되면 양쪽 유저의 `DUNBAR` 키가 지워진다.
- 친구 추가와 라벨 멤버 변경은 캐시를 지우지 않는다.
- 멤버가 50명을 넘는 라벨의 관계망을 조회하면 친밀도 상위 50명만 노드로 돌아온다.
- 바꾼 라벨 쿼리는 기존 쿼리와 같은 노드·엣지를 돌려주고, PROFILE에 라벨 멤버의 Friendship 전체를 펼치는 단계가 없다.
