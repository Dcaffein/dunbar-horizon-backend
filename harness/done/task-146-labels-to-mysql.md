# Task-146: 라벨을 MySQL로 옮기고 친구 관계와 멤버십을 함께 정리한다

## Background

라벨은 소유자의 친구를 그룹으로 묶고, Buzz 수신자 지정과 라벨 관계망에 쓰인다. 현재 친구를 끊으면 커밋 이후 비동기로 라벨 멤버십을 삭제한다. 그 사이에 이전 멤버십이 조회될 수 있고, 멤버 추가와 친구 끊기의 경합으로 친구가 아닌 사용자가 라벨에 남을 수 있다.

## Objective

MySQL에 저장된 친구 관계를 사용해 라벨과 멤버십을 같은 DB에 저장한다. 친구 관계가 끝나면 양쪽 라벨의 멤버십도 같은 트랜잭션에서 정리한다.

## Decision

- 라벨의 ID·이름·소유자 ID는 라벨 한 행에 둔다. 멤버십은 `(label_id, member_id)` 복합 키를 가진 별도 테이블로 두고 라벨 삭제 시 함께 제거한다. 조회한 멤버 컬렉션을 통해 멤버십을 변경할 수 없게 한다.
- 단건 추가와 멤버 교체는 대상 친구 관계를 먼저 잠그고 관계가 유효한지 확인한다. 친구 끊기와 동일한 관계 잠금을 사용하며, 여럿을 잠글 때는 순서를 통일한다.
- 친구 끊기와 감쇠 아카이브로 활성 친구 관계를 끝낼 때 소유 방향 양쪽의 멤버십을 같은 MySQL 트랜잭션에서 삭제한다. 아카이브 시 기록 저장도 같은 트랜잭션에 포함한다.
- 아카이브 후보는 관계를 잠근 뒤 최신 친밀도로 다시 판정한다. 정리 대상 라벨은 멤버십 삭제 전에 라벨 ID 순서로 잠근다.

## Acceptance Criteria

- 기존 라벨 생성·이름 변경·조회와 멤버 추가·제거·교체가 같은 API 계약을 충족한다. 같은 사람을 같은 라벨에 중복 등록할 수 없다. 라벨 선택으로 Buzz 수신자를 찾는 경로가 동일한 멤버를 사용한다.
- 라벨 소유자만 삭제할 수 있고, 소유자가 라벨을 삭제하면 멤버십도 제거된다.
- 단건 추가 또는 멤버 교체가 친구 끊기와 겹쳐도 커밋 뒤 친구가 아닌 멤버가 남지 않는다.
- 친구 관계를 끝내는 트랜잭션이 실패하면 멤버십도 함께 롤백된다. 아카이브는 기존 기록을 유지하고, 새 기록 저장과 활성 관계·멤버십 정리를 원자적으로 처리한다.
