# Task-147: 관계망·기준 친구 추천·연결 중개인 조회를 MySQL로 옮긴다

## Background

관계망과 기준 친구 추천은 친구 관계, 라벨, 공개 설정을 Neo4j 쿼리에서 조합한다. 동일한 로컬 데이터로 관계망과 기준 친구 추천을 비교한 실험에서는 MySQL로 기존 결과를 재현할 수 있었다. 추천은 기준 친구와 친밀도가 높은 후보부터 공통 친구와 공유 라벨을 검사하고 필요한 추천 수가 차면 멈추는 쿼리가 비용을 줄였다.

## Objective

MySQL에 저장된 친구 관계와 라벨을 사용해 Dunbar 관계망, 라벨 관계망, 관계망의 상호 연결, 기준 친구 확장·추천, 공통 친구 기반 연결 중개인을 조회한다. 기존 API 응답과 노출 정책을 유지한다.

## Decision

- 그래프 결과의 친밀도 순위, 조회 인원 상한, 기존 공개 범위와 `isRoutable`을 어느 사용자 쪽에서 읽는지 보존한다.
- 기준 친구 확장과 추천은 서로 다른 후보 범위를 유지한다. 공통 친구 수와 기준 친구가 소유한 공유 라벨 수로 후보를 걸러내고, 기준 친구와 후보 사이의 친밀도 기준으로 기존 정렬·반환 개수 규칙을 적용한다.

## Out of Scope

- TrustChain과 MeetInMiddle을 사용하는 신규 소개 경로
- Dunbar 관계망의 표시 방식이나 제품 정책 변경

## Acceptance Criteria

- 동일한 사용자·친구·라벨 데이터를 양쪽에 넣었을 때 현재 관계망의 노드와 엣지, 기준 친구 확장·추천 대상과 친밀도 순위, 공통 친구 기반 중개인 목록과 전체 수가 일치한다. 동률에서 기존에 순서를 정하지 않은 경우에는 기존 결과 계약을 기준으로 비교한다.
- 공개 설정을 양쪽에서 다르게 둔 관계, 공유 라벨이 후보 자격을 바꾸는 경우, 친구가 없거나 추천이 비는 경우를 검증한다. 기준 친구를 지정해 Buzz를 발행할 때 기존과 같은 수신자가 선택된다.
- 친구가 많은 사례와 통과하는 추천 후보가 드문 사례에서 SQL 실행 계획과 로컬 조회 시간을 기록한다. 후보마다 별도의 DB 요청을 보내지 않는다.
