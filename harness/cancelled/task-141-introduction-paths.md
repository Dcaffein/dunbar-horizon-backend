# Task-141: 두 탐색을 하나의 소개 경로 기능으로 제공한다

> 취소 · `MeetInMiddlePathSearch`와 `TrustChainSearch`의 설계 기록을 보관한다.

## Background

기존 연결 중개인은 프로필에서 공통 친구를 보여준다. 공통 친구가 없는 대상에게도 아는 친구를 통해 소개를 부탁할 수 있는지 확인할 수 있으면, 사용자는 대상에게 연락할 방법을 고를 수 있다.

새 친구의 친밀도는 약 `0.3`에서 시작한다. 앱 안에서 교류가 쌓이기 전에도 짧은 소개 경로는 유용하고, 교류가 쌓이면 강한 관계를 따라 더 먼 경로를 찾을 수 있다.

## Objective

사용자가 대상을 지정하면 **소개 경로** 기능이 `MeetInMiddlePathSearch`와 `TrustChainSearch` 두 조회를 실행하고 결과를 하나의 응답으로 제공한다. 사용자는 경로의 단계와 자신이 아는 중개인을 확인하고, 익명으로 표시된 중간 사람이 있다면 그 사람과 직접 연결된 내 친구 중 누구에게 소개를 부탁할 수 있는지 판단할 수 있다.

## Decision

### 두 탐색의 역할

| 탐색 | 역할 | 후보와 친밀도 기준 |
|---|---|---|
| `MeetInMiddlePathSearch` | 양쪽에서 최대 2홉씩 펼쳐 2~4홉 소개 경로를 찾는다. | 양쪽 유효 1홉 목록 전체를 보관한다. 한 홉 더 펼칠 때는 각 목록에서 친밀도 상위 50명을 사용한다. 개별 관계는 초기 친밀도 `a = 21.4 / (21.4 + 50)` 이상이어야 하고, 완성 경로의 친밀도 곱은 홉 수와 관계없이 `a²` 이상이어야 한다. |
| `TrustChainSearch` | 가까운 친구에서 출발해 높은 연결 강도를 유지하는 경로를 가변 길이로 찾는다. | 출발점의 직접 친구 중 친밀도 상위 15명으로 첫 홉을 제한한다. `h`번째 홉까지의 친밀도 곱이 매번 `0.7 × 0.75^(h−1)` 이상이어야 한다. |

`MeetInMiddlePathSearch`는 양쪽 부분 경로를 만나는 사람 기준으로 이어 `1+1`, `1+2`, `2+1`, `2+2`를 검사한다. 두 엣지가 각각 `a` 이상이면 2홉 부분 경로의 곱도 `a²` 이상이다. 따라서 새 친구 관계 두 개로 이어진 공통 친구 소개는 후보가 되고, 더 긴 경로는 전체 곱이 같은 기준을 넘어야 한다. 로컬 합성 데이터의 다섯 사례에서 확장 대상을 양쪽 150명에서 50명으로 줄여도 최종 추천은 같았고 DB Hits는 39~70% 줄었다.

`TrustChainSearch`의 첫 홉 하한은 `0.7`이다. 이후 하한은 홉마다 25%씩 내려간다. 경로 전체의 고정 친밀도 하한 `F`는 두지 않는다. 홉별 곱 조건은 여러 관계의 강도를 함께 평가하며, 별도의 개별 엣지 하한 `0.5`는 확정하지 않았다.

### 경로의 자격과 노출

- 대상이 이미 내 친구인 경우에도 중개인이 있는 경로를 찾는다. `나 → Target` 한 홉은 소개 경로에 포함하지 않는다. Target에 처음 도달하면 그 경로를 끝낸다.
- 경로에서 같은 사람을 다시 방문할 수 없다. 나와 Target을 제외한 중간 사람 중 **출발점의 직접 친구가 아닌 사람은 최대 한 명**이다. 직접 친구 여부는 전체 친구 관계에서 판단하며, 상위 15명이나 50명에 들었는지와 무관하다.
- 각 관계는 최종 진행 방향에서 **도착 사용자 쪽**의 `isRoutable`이 `true`일 때만 사용한다. Target 쪽에서 역으로 펼칠 때도 최종 경로의 방향으로 확인한다.
- 모르는 중간 사람은 `???`로 표시한다. 응답에 그 사람의 ID, 프로필, 조회를 가로질러 추적할 수 있는 고정 키를 싣지 않는다. 친밀도와 경로 점수는 서버의 후보 선정에만 사용한다.
- 모르는 중간 사람과 직접 연결된 내 친구가 여러 명이면, 소개 요청을 맡을 수 있는 후보를 구분할 수 있어야 한다.

### 병렬 조회와 500ms 예산

- 한 요청에서 두 탐색을 **서로 다른 읽기 트랜잭션으로 병렬 실행**한다. 동일한 사용자 순서의 경로는 서버에서 하나로 합쳐 단일 응답으로 반환한다.
- `MeetInMiddlePathSearch`는 최대 세 경로를 고른다. 누적 친밀도를 비교하고, 같은 친구를 통하는 두 번째 경로보다 첫 중개 친구가 다른 경로를 우선한다.
- `TrustChainSearch`는 Neo4j 쿼리 한 번으로 탐색하며, DB에서 전체 후보를 정렬해 상위 세 건으로 자르는 절차를 제거한다. 백엔드는 전달된 완성 경로를 순차적으로 받아 점수순으로 최대 세 개를 보관한다. 점수가 같으면 홉이 적은 경로를 우선한다.
- TrustChain의 **500ms 예산은 병렬 조회 시작 시점부터** 세며 DB 연결을 기다리는 시간도 포함한다. 예산이 끝나면 그때까지 백엔드가 받은 유효 경로를 확정한다. 한두 개만 받았으면 그만큼 반환하고, 하나도 받지 못했으면 `MeetInMiddlePathSearch` 결과만 사용한다. 시간 초과와 정상 종료 후 경로 없음은 구분해서 기록한다.
- 마감에 도달하면 해당 TrustChain 트랜잭션에 취소를 요청한다. 응답은 취소 확인을 기다리지 않는다. 마감 이후 도착한 경로는 응답에 포함하지 않는다. 마감 시 순위는 그때까지 받은 경로 기준이다.

## Acceptance Criteria

- 소개 경로 한 요청이 두 조회를 별도 읽기 트랜잭션에서 병렬로 수행하고, 중복 경로를 합쳐 한 응답으로 반환한다. 양쪽에서 나온 동일한 경로는 한 번만 표시된다.
- `MeetInMiddlePathSearch`에서 양쪽 51번째 이후 친구가 유일한 유효 공통 친구라면 2홉 경로를 찾는다. 각 쪽의 추가 확장은 상위 50명까지만 사용한다. 초기 친밀도 두 개로 이뤄진 경로는 통과하고, 개별 관계 또는 완성 곱의 하한을 어기는 경로는 탈락한다.
- `TrustChainSearch`에서 첫 홉 상위 15명 제한과 매 홉 누적 곱 기준을 검증한다. 최종 곱을 충족하더라도 앞선 홉에서 이미 기준을 어긴 경로는 반환하지 않는다.
- 이미 직접 친구인 Target도 중개인이 있는 경로를 조회한다. 재방문, 모르는 중간 사람 두 명 이상, 최종 진행 방향에서 공개되지 않은 관계가 있는 경로는 탈락한다. 역탐색 쪽의 공개 여부가 비대칭인 사례를 포함한다.
- 응답에서 모르는 중간 사람의 신원과 친밀도 점수가 드러나지 않는다. 익명 사람과 직접 연결된 내 친구가 두 명이면, 어느 친구에게 소개를 부탁할 수 있는지 각각 확인할 수 있다.
- TrustChain 마감 전 받은 경로가 0·1·2·3개 이상인 경우를 각각 검증한다. 1·2개도 보존하며, 최대 세 개를 고른다. 마감 시 남은 TrustChain 조회에 취소를 요청한다. 마감 이후 결과나 취소 확인 때문에 이미 완료된 `MeetInMiddlePathSearch` 결과의 반환이 늦어지지 않는다.
